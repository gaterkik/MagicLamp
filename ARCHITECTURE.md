# Системная Архитектура: MagicLamp (ESP32-C6)

## 1. Аппаратная спецификация и схема пинов (Hardware & Pinout)
- **Микроконтроллер:** ESP32-C6 Mini (RISC-V, 160 МГц, 4MB Flash).
- **Блок питания:** Внешний 5V / 3.0A. Программный лимит тока: строго **2500 мА (2.5 А)**.

### Таблица пинов (Изменять ЗАПРЕЩЕНО):
| Устройство | Линия | Пин ESP32-C6 | Примечание по реализации |
| :--- | :--- | :--- | :--- |
| **LED-матрица 16x16** | `DIN` | **GPIO 2** | WS2812B, 256 LED, вход снизу (`Y=0`), горизонтальная змейка, кольцо по `X`. |
| **Кнопка TTP223** | `I/O` | **GPIO 7** | HIGH при касании. Удержание от 700 мс шлет тики каждые 40 мс. Сброс — 5 кликов. |
| **Гироскоп GY-521** | `SDA` / `SCL` | **GPIO 6 / GPIO 5** | Программный Open-Drain I2C драйвер (Bit-Bang, без `Wire.h`), авто-реверс пар `(SDA=6, SCL=5)` и `(SDA=5, SCL=6)`. Принимать любой `WHO_AM_I` при наличии I2C ACK! |
| **Микрофон INMP441** | `SCK`/`WS`/`SD` | **GPIO 18 / 19 / 20** | Аппаратный I2S Standard Mode (`driver/i2s_std.h`), DMA + 128-pt FFT + AGC. |

### Требования к диагностике и шине I2C (`ImuMpu6050`):
- **Отказ от библиотеки `<Wire.h>`:** Полностью отказаться от библиотеки `<Wire.h>` для опроса GY-521 из-за конфликта менеджера пинов `esp32-hal-periman` в Arduino Core 3.x.
- **Собственный программный Open-Drain I2C драйвер (Bit-Bang):** Реализовать внутри `imu_mpu6050.cpp` собственный самодостаточный программный драйвер Open-Drain I2C (Bit-Bang с `delayMicroseconds(5)`, где лог. `1` = `INPUT_PULLUP`, лог. `0` = `pinMode(OUTPUT)` + `digitalWrite(LOW)`).
- **Проверка физической подтяжки линий SDA/SCL:** Для проверки физического контакта линий SDA/SCL перед чтением включать `pinMode(pin, INPUT_PULLDOWN)` на 50 мкс: так как на модуле GY-521 распаяны внешние подтяжки 2.2 кОм к 3.3V, при реальном физическом контакте пин останется `HIGH`, а неприпаянный/висящий в воздухе пин покажет `LOW` (выводить это честно в статус).
- **Сканирование адресов и реверс пар пинов при старте:** При старте сканировать адреса сначала на паре `(SDA=6, SCL=5)`, затем при отсутствии ACK — на реверсной паре `(SDA=5, SCL=6)`.
- **Оптимизация фонового ретрая (Защита от фризов):** В режиме Fallback категорически запрещено сканировать все 112 адресов (`0x08..0x77`) каждые 5 секунд в главном цикле (это вызывало микро-подвисания в эффекте «Костер»!). В фоновом ретрае проверять ТОЛЬКО 2 адреса (`0x68` и `0x69`), чтобы время проверки не превышало 0.3 мс.
- **Инициализация и чтение данных:** При обнаружении ответа на `0x68`, `0x69` (или любом другом адресе I2C) выводить точный адрес и регистр `WHO_AM_I` (0x75) в статус, будить чип (`0x6B = 0x00`) и читать регистры ускорения (`0x3B..0x40`). При отсутствии ACK выводить подробную диагностику уровней пинов.

## 2. Версионирование и конфигурация сети (`version.h` и `secrets.h`)
1. **`include/version.h`:** Содержит `#define FIRMWARE_VERSION "0.3.0"`.
2. **`include/secrets.h` (обязательно добавлен в `.gitignore`):**
   Содержит локальные учетные данные Wi-Fi (`WIFI_SSID`, `WIFI_PASSWORD`).
   Также создается шаблон `include/secrets.example.h` (с пустыми полями) для репозитория GitHub.
3. **Логика подключения `WiFiManager` (`src/network/wifi_manager.*`):**
   - При старте пытается подключиться к сети из `include/secrets.h` (или сохраненной в `Preferences` NVS).
   - Для максимальной стабильности радиоканала отключает энергосбережение Wi-Fi: `WiFi.setSleep(false)` и полностью выключает AP (`WiFi.enableAP(false)`) при успешном подключении к STA.
   - Поднимает mDNS с именем `magiclamp` (`http://magiclamp.local`).
   - Если за 15 секунд подключиться к роутеру не удалось — автоматически поднимает точку доступа `MagicLamp-Setup` (с Captive Portal для ввода нового Wi-Fi).
   - Поддерживает фоновый `ArduinoOTA` для мгновенной заливки прошивки по локальной сети без кабеля.

## 3. Архитектура облачного обновления с GitHub (`src/network/ota_github.*`)
- **Эндпоинт проверки:** `https://api.github.com/repos/gaterkik/MagicLamp/releases/latest`
- **Транспорт и стабильность HTTPS на ESP32-C6:**
  - Обязательное отключение энергосбережения Wi-Fi: `WiFi.setSleep(false)`.
  - Использование `WiFiClientSecure` с `client.setInsecure()`.
  - Установка таймаута TLS рукопожатия и сокета: 15 секунд.
  - До 3 автоматических повторов с паузой при ошибке соединения (код возврата `< 0`, например `-1` connection failed).
  - **Разделение TLS-сессий при HTTP 302 редиректе:** GitHub перенаправляет скачивание релиза с `github.com` на CDN `objects.githubusercontent.com`. Во избежание сбоев TLS-сессии на ESP32-C6 перенаправление обрабатывается с явным закрытием предыдущего соединения и созданием нового чистого экземпляра `WiFiClientSecure` для целевого URL скачивания `firmware.bin`.
- **Заголовки запроса:** Обязателен заголовок `User-Agent: MagicLamp-ESP32C6-OTA`.
- **Алгоритм:**
  1. Парсинг ответа GitHub API `/releases/latest`: во избежание проблем с усечением крупного JSON извлекать `"tag_name"` потоковым поиском/фильтром. Сразу производить нормализацию (отсекать префикс `v`) и сравнение с `FIRMWARE_VERSION`. Если версии совпадают — немедленно завершать проверку со статусом `"Установлена актуальная версия"` без лишней загрузки сети.
  2. Определение URL для загрузки `firmware.bin`: извлекать `browser_download_url` из `assets` или гарантированно использовать детерминированный URL прямой загрузки `https://github.com/gaterkik/MagicLamp/releases/latest/download/firmware.bin` (если поле `browser_download_url` не попало в буфер или было обрезано).
  3. Скачивание потока и запись во флеш через стандартную библиотеку `<Update.h>` (`Update.begin(contentLength, U_FLASH)` -> `Update.writeStream()` -> `Update.end(true)`).
  4. Перед стартом прошивки матрица гасится (или показывает спокойный индикатор), после успешного `Update.end(true)` вызывается `ESP.restart()`.
- **Буфер статуса UTF-8:** Увеличить размер буфера статуса `m_status` с 64 до `192` байт, чтобы кириллические строки в UTF-8 (2 байта на символ, например `"Установлена актуальная версия (v0.5.3)"`) никогда не обрезались.

## 4. Архитектура Веб-интерфейса (`src/network/web_server.*`)
- Работает на базе стандартного `WebServer` (порт 80) из состава Arduino Core 3.x без тяжелых сторонних зависимостей.
- Фронтенд (HTML/CSS/JS) встроен во Flash как сжатая строка `PROGMEM` в `src/network/webui_html.h`, чтобы веб-интерфейс работал всегда, даже после OTA-обновления одного только `firmware.bin`.
- **Векторный Favicon:** Добавить векторную SVG-иконку вкладки браузера (Favicon в виде светящейся неоновой лампы) через `<link rel="icon" type="image/svg+xml" href="data:image/svg+xml,...">` в `webui_html.h` и маршрут `GET /favicon.ico` в `WebServer`.
- **REST API:**
  - `GET /api/status` — JSON со всеми метриками (температура чипа, RSSI, IP, версия прошивки, текущий эффект, яркость, статус GY-521, статус последней проверки GitHub OTA).
  - `GET /favicon.ico` — отдача SVG-иконки лампы для браузеров.
  - `POST /api/control` — изменение включения, яркости, номера эффекта (0..9), скорости и чувствительности микрофона.
  - `POST /api/ota/check` — запуск проверки и обновления с GitHub Releases.
  - `POST /api/ota/upload` — прямая загрузка файла `firmware.bin` из браузера через `Update`.

## 6. Архитектура LittleFS, EffectVM и Магазина эффектов (Фаза 4)
- **ВАЖНОЕ ОГРАНИЧЕНИЕ OTA:** Запрещено изменять файл `partitions.csv`! Использовать существующий раздел `littlefs` в текущей таблице разделов, чтобы сохранить 100% совместимость с беспроводным обновлением OTA с версии v0.4.0.
- **Движок подгружаемых эффектов `EffectVM` (`src/effects/effect_vm.h`, `src/effects/effect_vm.cpp`):**
  - Читает компактные JSON/ключ-значение дескрипторы эффектов `.eff` из LittleFS (`/effects/<id>.eff`).
  - Поддерживает настраиваемые цветовые палитры, параметры скорости/масштаба/интенсивности и 6 параметрических/шейдерных ядер рендеринга на бесшовном цилиндре 16x16 (60 FPS):
    1) `aurora` (Северное сияние — волнообразные вертикальные ленты с шумом Перлина),
    2) `matrix_rain` (Цифровой дождь «Матрица» с бегущими вертикальными шлейфами),
    3) `lava_lamp` (Лава-лампа — медленная тепловая конвекция крупных восковых капель),
    4) `vortex` (Галактическая спираль — вращающиеся спиральные рукава вокруг цилиндра),
    5) `fireworks` (Фейерверк — пуск ракет снизу вверх и кольцевой разлет искр с гравитацией),
    6) `cyber_pulse` (Киберпанк-пульс — неоновые кольца и математический RPN/волновой шейдер с реакцией на звук/время).
- **Менеджер магазина `StoreManager` (`src/network/store_manager.h`, `src/network/store_manager.cpp`):**
  - Монтирует файловую систему с явным указанием метки раздела `LittleFS.begin(true, "/littlefs", 10, "littlefs")` (и резервной попыткой `LittleFS.begin(true, "/littlefs", 10, "spiffs")`).
  - **NVS-резерв и RAM-кэш (Zero-Breakage Storage):** Если раздел LittleFS на текущей разметке Flash не монтируется — автоматически переключать хранение скачанных `.eff` файлов в энергонезависимую память `Preferences` (NVS, namespace `"eff_store"`) и RAM-кэш, чтобы Магазин эффектов работал на 100% без перепрошивки таблицы разделов по USB.
  - Сканирует установленные эффекты (из LittleFS или NVS/RAM) и регистрирует их в `EffectManager`.
  - Умеет по HTTPS (`WiFiClientSecure` с `setInsecure()` + `HTTPClient`) скачивать файл `.eff` из `https://raw.githubusercontent.com/gaterkik/MagicLamp/main/store/effects/<id>.eff`, проверять его валидность, сохранять (в LittleFS либо в NVS/RAM-бэкенд) и сразу активировать эффект без перезагрузки лампы.
  - **Стабильность HTTPS на ESP32-C6:** `WiFi.setSleep(false)`, таймаут TLS-соединения 15 секунд, до 3 автоматических повторов при ошибке соединения (`< 0`), корректная обработка редиректов с пересозданием сессии при смене хоста.
- **Новые REST API эндпоинты в `WebServer`:**
  - `GET /api/store/installed` — список установленных в LittleFS/NVS `.eff` эффектов + статистика памяти (`usedBytes`, `totalBytes`, признак NVS fallback).
  - `GET /api/store/catalog` — проксирование/кеширование или получение `manifest.json` с GitHub (`https://raw.githubusercontent.com/gaterkik/MagicLamp/main/store/manifest.json`), плюс в самом WebUI фронтенде прямой `fetch` каталога с GitHub Raw с fallback на `/api/store/catalog`.
  - `POST /api/store/install` — скачивание и установка выбранного эффекта (`id`, `url`) с GitHub в хранилище.
  - `POST /api/store/delete` — удаление эффекта из хранилища.

## 7. Требования к эффектам: Эффект «Костер» (`Fire`)
- **Формирование вертикальных языков пламени:** Убрать избыточное горизонтальное размытие («рябь на воде»). Ввести неоднородную вертикальную маску тяги и остывания по столбцам `X (0..15)` на основе шума Перлина, чтобы формировались отдельные выразительные вертикальные языки пламени разной высоты (`Y=0..12`).
- **Искры (угольки):** Количество искр снизить в 3 раза (не более 1–2 одновременно). Цвет искр — строго красно-оранжевый/алый уголек (`CRGB(220, 35, 0)` -> `CRGB(100, 5, 0)`), без белого цвета. Верхняя четверть лампы (`Y=13..15`) остается темной зоной для плавного затухания искр.

## 8. Архитектура звукового тракта (`MicI2S` и `AudioReactive`)
- **Устранение бага «оглушения»:** Убрать завышающийся адаптивный `noiseFloor`, блокировавший слабые и средние звуки после пиковых всплесков/хлопков.
- **Noise Gate и АРУ:** Использовать низкий фиксированный порог тишины (Noise Gate только для отсечки собственного шума микрофона I2S в абсолютной тишине), быструю симметричную релаксацию АРУ (AGC) и масштабирование с учетом ползунка чувствительности `sensitivity`.
- **Взрывная динамика:** Столбики спектра должны живо прыгать на всю высоту цилиндра (`Y=0..15`), а при громком звуке, хлопке или мощном басовом ударе яркая световая волна пробивает цилиндр снизу до самого верха.

## 9. Управление эффектами, скорость и индивидуальные профили в NVS (`EffectManager`, `CoreEffects`, `MathEffects`, `EffectVM`)
- **Регулировка скорости (`speed` 1..255):**
  - `PerlinNoise`: скорость фазового смещения Z/t и масштабирования шума.
  - `GameOfLife`: интервал смены поколений от 400 мс (на минимальной скорости 1) до 40 мс (на максимальной скорости 255).
  - `LorenzAttractor`: шаг численного интегрирования `dt` и количество подшагов на кадр.
  - `Metaballs`: скорость перемещения центров сферических источников.
  - `EffectVM` (`lava_lamp`, `matrix_rain`, `aurora`, `vortex`, `cyber_pulse`): множитель `dt` физического и анимационного времени.
- **Индивидуальные NVS-профили:**
  - Хранить в NVS индивидуальную структуру настроек для каждого эффекта (массив профилей `brightness`, `speed`, `sensitivity` по индексу эффекта).
  - При переключении эффекта автоматически загружать его персональные параметры яркости и скорости.
  - Отложенная запись измененных настроек в NVS (debounce 2 секунды) для защиты ресурса флеш-памяти при плавном перемещении ползунков.
